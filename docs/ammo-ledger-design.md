# 実包管理簿（銃の使用・実包の受払）設計書

作成: 2026-11-23　対象: 館山ジビエ基幹システム（本番は未変更・承認待ち）

---

## 1. 目的

- 止めさし・有害駆除・狩猟・標的射撃で使った実包を、**その場で1行ずつ記録**し、いつでも「現在数」が分かるようにする。
- 法定の「実包等の保管管理簿（別添３）」と**同じ書式で出力**できるようにする（検査で提示・3年保存）。
- 個体（individuals）の「止めさし＝銃」と実包の消費を**つなぐ**（1個体の一生の線に「どう止めさしたか」を載せる）。

## 2. 現状（2026-11-23 実測）

| 項目 | 状態 |
|---|---|
| 原本 | Google Drive の Excel（別添３の書式・許可者ごと・番径でまとめて計数） |
| 記入 | 手作業。使用から記入までに間が空き、記入漏れが起きやすい |
| 止めさしとの関係 | 個体の止めさし（ナイフ／銃）は individuals にあるが、使った実包とはつながっていない |
| システム | 銃・実包の表は無い |

**懸念:** Excel の現在数と手元の実数が合っているかを、定期的に照合する仕組みが無い。番径でまとめて数えるため、弾の種類（スラッグ／散弾）ごとの残りも分からない。

（具体的な残数・使用日・場所は保安上の情報なので、公開リポジトリには書かない。）

## 3. 法定の記載事項（別添３の列に合わせる）

| 列 | 内容 | 例 |
|---|---|---|
| 年月日 | 受払の日 | 2026-11-01 |
| 目的別 | 無・譲受／許・譲受／狩猟／有害鳥獣／標的／残弾処理標的／廃棄／譲渡 | 有害鳥獣 |
| 住所・場所 | 使った場所、または購入先の住所 | 千葉県◯◯市◯◯ |
| 氏名・名称 | 購入先・射撃場など（使用時は空欄でよい） | 渡辺銃砲火薬店 |
| 実包 | 番径（散弾銃）／種別（ライフル）、受・払 | 12番・払2 |
| 空砲・雷管・火薬 | 受・払・残 | （通常は使わない） |
| 現在数 | 前の行の現在数＋受−払 | 自動計算 |
| メモ（任意） | 狩猟同伴者・獲物捕獲数（使用実績報告用） | イノシシ1 |

- 保管上限: 実包・空砲 **800個**、銃用雷管 2,000個、火薬 5,000g → 超えそうなら画面で警告。
- 保存期間: 最後の記入から **3年**。行は消さない。

## 4. データの形（追加のみのマイグレーション）

### 4.1 `firearm_holders`（許可を持つ人）
| 列 | 型 | 説明 |
|---|---|---|
| id | uuid | |
| name | text | 氏名 |
| permit_no_hint | text | 許可書番号は**置かない**か下数桁だけ（出力時に本人が入れる） |
| gauge | text | 主に使う番径（12番） |
| is_active | boolean | |

### 4.2 `ammo_ledger`（受払の1行＝帳簿の1行）
| 列 | 型 | 説明 |
|---|---|---|
| id | uuid | |
| holder_id | uuid | 誰の帳簿か |
| happened_on | date | 年月日 |
| purpose | text | 目的別（3章の8種類だけ受け付ける） |
| place | text | 住所・場所 |
| counterpart | text | 氏名・名称（購入先・射撃場） |
| ammo_kind | text | 番径または種別（12番・スラッグ など） |
| qty_in / qty_out | integer | 受・払（どちらか片方） |
| individual_id | text | 止めさしの個体（任意。individuals.label_id） |
| companions / catch_note | text | 同伴者・獲物（使用実績報告用・任意） |
| source | text | 入力元（止めさし画面／帳簿画面／Excel取込） |
| cancels_id | uuid | 取り消す行（**訂正は取消行を足す**。元の行は消さない・書き換えない） |
| created_at / created_by | | |

- 現在数は保存しない。**行の合計から毎回計算**する（書き換えでずれない）。
- 現在数がマイナスになる行は保存させない（記入漏れの合図として画面に出す）。

## 5. 画面

1. **捕獲票（capture-form）**: 止めさしで「銃」を選んだら「使った実包: [  ]発（スラッグ／散弾）」を出す。保存すると ammo_ledger に「有害鳥獣・払」の行が個体つきで入る。保存に失敗したら画面に出す（黙って捨てない）。
2. **実包管理簿（index.html の新タブ・スタッフキー必須）**
   - 現在数・今年の使用数・上限まで の残り
   - 行の追加（購入・射撃場・狩猟・廃棄）／取消行の追加
   - 一覧（別添３と同じ列の並び）
3. **出力**: 別添３の書式で Excel（12行ごとにページ・前葉繰越し・注意書き入り）。年度の「狩猟・有害の使用実績」集計も出す。
4. **Excel 取込（1回だけ）**: 既存の Excel の行を取り込み、現在数を手元の実数と照合してから、続きをシステムで書く。

## 6. 安全・個人情報

- 表は RLS で**直接読めない**。読み書きはスタッフキー確認つきの DB 関数だけ（捕獲者台帳と同じ方式）。
- 許可書番号の全桁・住所はシステムとリポジトリに置かない（リポジトリは公開）。出力時に本人が入れる。
- テストは架空の人・架空の数で行う。

## 7. 決めること（着手前）

1. **記入漏れの照合**: 既存の Excel の現在数と手元の実数（番径・種類ごと）を合わせる。合わない分は日付・目的・場所・数を確認して追記する。
2. **銃・実包の種類**: スラッグと散弾を分けて数えるか（現行の Excel は番径でまとめている）。
3. **使う人**: 許可者本人以外に記録する人がいるか。
4. **原本の扱い**: システムを正本にして Excel は出力物にするか、当面は Excel を正本のまま併用するか。

## 9. テスト（tests/e2e/ に追加）

- 受払を入れると現在数が正しく増減する／マイナスになる行は保存されない
- 取消行で元に戻る・元の行は残る
- 止めさし「銃」で保存すると帳簿に1行入り、個体とつながる／失敗は画面に出る
- 出力した Excel の列・前葉繰越し・ページ区切りが別添３どおり
- 上限 800 個に近づくと警告／スマホの幅ではみ出さない

# 個体番号 採番一本化（A案）設計書

## 背景・問題
個体管理番号（`TGC-08-T###` / `M###` / `シ###` 等）と通し番号（イノシシ `serial_number`）に
「番号の飛び（欠番）」が繰り返し発生した。

### 実際に起きた事象
- M170 の次が M181（M171〜180 が欠番）
- キョン キ052 の次が キ057（キ053〜056 が欠番）
- 付け替え後も、翌日の南房総個体が再び M181（M177〜180 が欠番）

### 根本原因
採番の権限（オーソリティ）が **2系統** に分かれていた。
1. **捕獲票アプリ（capture-form.html）**: 端末 localStorage のカウンタと `Math.max(DB最大+1, 端末カウンタ)` で採番。
   端末カウンタは一度上がると下がらず、**オフライン登録・下書き・試し・書き直し**で先行ドリフトすると
   恒久的に番号が飛ぶ。
2. **台帳スプレッドシート同期**: `label_id` をキーに individuals へ upsert。台帳側で手採番した番号を持ち込む。

この2系統が同じ番号空間へ、互いに調整せず個体を入れるため、順序の乱れと欠番が生じた。

PR #190/#191 で「オンライン かつ 未送信キュー空なら DB 最新へ自己修復」を入れたが、
**オフライン登録や開きっぱなしの古い画面では自己修復が効かず**、再発した。

## 方針（A案）: 発番を DB に一本化する
番号を振る唯一の権限を **DB** に置き、**INSERT の瞬間に原子的に採番**する。
端末カウンタは採番の権限から外す（表示上の「予定番号」プレビューにのみ使う）。

### 中核: BEFORE INSERT トリガ `tgc_assign_individual_number`
`individuals` への INSERT で、**センチネル `label_id = 'AUTO-<接頭辞>'`** が来たときだけ、
DB 側で番号を確定する。

- `label_id` が `AUTO-` で始まらない INSERT（＝台帳同期・他ツール・編集の PATCH）は**一切触らない**
  → 影響範囲は「アプリの新規登録経路」だけに限定。
- センチネルのとき:
  - `pg_advisory_xact_lock` で採番を直列化（同時登録の競合を防止）
  - イノシシ: `serial_number = max(有効なイノシシ serial)+1`、`label 番号 = max(有効な当該接頭辞ラベル)+1`
  - その他の種: `label 番号 = max(有効な当該接頭辞ラベル)+1`、`serial_number = label 番号`（他種は通し番号=管理番号）
  - 削除済み（`deleted_at`）は基準から除外＝欠番は繰り上げて再利用
  - `SECURITY DEFINER` で RLS を跨いで全行の最大値を見る

### なぜ欠番・重複が起きないか
- **オンライン**: INSERT 応答で確定番号が返る。端末カウンタは無関係。
- **オフライン**: レコードはセンチネルのままキューへ。復帰時に順に INSERT され、
  各 INSERT でトリガが `DB最大+1` を採番 → 送信順に連番。端末カウンタのドリフトは番号に影響しない。
- **複数端末同時**: `advisory_xact_lock` で直列化され、常に一意・連番。
- **試し入力・書き直し・下書き**: 確定（INSERT）しない限り番号を消費しない。
  削除した最新番号は次の登録が繰り上げて再利用。

### 台帳スプレッドシート同期の扱い（二重採番の解消）
同期は `AUTO-` センチネルを使わず、従来どおり実番号で upsert する＝**トリガは同期を触らない**。
ただし今後は「番号の唯一の正はDB」とし、同期は次のいずれかに寄せる（運用ルール）:
- (推奨) 台帳側は番号列を編集せず、**DB が採番した番号を台帳へ書き戻す**向きに統一。
- または同期スクリプトは「DBに無い個体だけを、番号を持ち込まず `AUTO-` で挿入」し、番号はトリガに任せる。

## クライアント変更（capture-form.html）
- 新規登録（通常経路。hunter/搬入待ち/編集/空枠マッチを除く）では、
  `label_id = 'AUTO-' + 接頭辞`、`serial_number = null` を送る。
- 保存レスポンスの `label_id` / `serial_number`（＝DB確定値）を表示・確認・以後の印刷に使う。
- 端末カウンタ（`tgc_next_serial_*` / `tgc_next_label_*`）は採番の権限から外す。
  `refreshIndividualNumber` は「予定番号（DB最大+1＋未送信キュー件数）」のプレビュー表示に限定。
- オフライン: 従来どおりキュー。番号はセンター復帰時（sync の INSERT）に確定。
  ラベル印刷は搬入一覧の各個体から（確定番号で）行う。

## 影響を受けない経路（設計上の安全策）
- 台帳同期 INSERT（実ラベル）… センチネルでないため対象外
- 既存データの編集（PATCH/UPDATE）… INSERT トリガの対象外
- 空枠マッチ（先に用意した通し番号スロットへの PATCH）… 対象外
- 搬入待ち / 捕獲者モード（`仮-...` ラベル）… センチネルでないため番号を付けない（受入時に AUTO で確定）

## テスト
- DB: センチネル INSERT が連番・一意になる／削除番号の繰り上げ／同期（実ラベル）は不変／
  他種（シ・ア・ハ・キ）の採番／並行 INSERT で重複しない。
- クライアント: 通常登録が `AUTO-<接頭辞>` を送る／レスポンスの確定番号を表示に反映／
  搬入待ち・編集はセンチネルを送らない。
- 全種の欠番チェック（毎日 12:00 の定期 Routine）で継続監視。

## 移行手順
1. マイグレーションでトリガを追加（この時点では誰も `AUTO-` を送らないので無害）。
2. クライアントを `AUTO-` 送信へ切替（PR）。
3. 本番反映後、実登録で連番を確認。定期チェックで欠番ゼロを継続確認。
4. 端末カウンタの旧ロジックは段階的に撤去（プレビュー専用へ）。

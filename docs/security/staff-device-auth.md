# スタッフ認証と端末トークン（個体データの編集・削除）

館山ジビエセンターの現場・事務の端末は**共有**が前提。個体データ（市役所提出データ）
の**編集・削除**は、なりすまし・改ざんを防ぐためスタッフ認証を必須にしている。

## しくみ

- **新規の捕獲登録はスタッフ認証不要**（捕獲者が自分で入力できる。列ホワイトリスト方式の
  公開RPC `public_capture_submit` 経由。買取金額・肉ランク・放射能結果などは設定不可）。
- **既存データの編集・削除・個体番号変更**はスタッフ認証が必要。
  - 端末に**生のスタッフキーは保存しない**。
  - 初回だけスタッフキーを入力すると、その端末に**端末トークン**が発行される。
  - DBには**トークンのsha256ハッシュのみ**保存（表 `staff_device_tokens`）。
  - 以後この端末では**再入力不要**。**最終利用から30日**で自動失効（スライド式）。

localStorage に入るのは `tg_device_token`（トークン。生キーではない）。

## 端末の初回設定（使い捨て招待リンク・生キーはURLに乗せない）

現場端末には**生スタッフキーを一切入力・保存しない**。管理者が発行する**使い捨ての招待リンク**で認証する。

1. 業務OS（index.html）の個体一覧で **「🔗端末認証リンク」** を押す。
   - サーバが**招待トークン（enrollment token）**を発行（十分な乱数・**DBはsha256のみ**・**有効期限10分・1回限り**）。
   - `…/capture-form.html#enroll=<使い捨てトークン>` のリンクがコピーされる。**生スタッフキーはURLに含まれない**。
   - 招待は **1端末につき1回発行**する（10分・1回限りのため）。
2. そのリンクを対象端末で**一度だけ開く**。
   - 端末は `#enroll=` を読み取り→サーバで **SELECT FOR UPDATE で交換**（未使用・期限内を検証）→**使用済み化と端末トークン(`dt_`)発行を単一トランザクションで**実施→**URLフラグメントを即時除去**。
   - 同じ招待を2台で同時に開いても**成功するのは1台だけ**。期限切れ・使用済み・失効済みは拒否。
   - 同一端末では capture-form / record-list の両方が同じ `dt_` トークンで認証される（同一オリジンのlocalStorage共有）。
3. 以後その端末では、正式番号での登録・編集・削除に**再入力不要**（最終利用から30日スライドで実質失効しない）。

> 個体の編集・削除・番号変更・センター受入RPCは**`dt_`端末トークンのみ**を受け付ける（生スタッフキーは受理しない）。
> 生スタッフキーは**招待の発行**（管理者）と**キー変更（回復コード）**だけに使う。
> 一般の捕獲者（`?hunter=` で開くモード）は認証不要。

### 招待・端末の監査
- `enrollment_tokens`: 発行(`created_at`/`issuer`)、使用(`used_at`/`device_token_id`)、失効(`revoked_at`)、期限(`expires_at`)。
- キー変更（`admin_rotate_staff_key`）時に、全端末トークンと**未使用の招待**を一括失効。
- `security_events`: `enrollment_issued` / `device_enrolled` / `device_registered` / `device_revoked` / `staff_key_rotated`。

> 補足: 業務OS(index.html)の顧客台帳RLSは暫定的に生スタッフキー(x-staff-key)を使う（**手入力のみ・URL配布は廃止**）。
> このRLSの端末トークン/Supabase Auth化は後続。個体書込は本方式（`dt_`）に移行済み。

## 端末の認証を解除したいとき（共有端末・紛失・貸与終了）

各画面（捕獲票入力 / 業務OSの個体一覧 / 搬入一覧）の
**「🔓認証解除」ボタン**を押す。その端末のトークンが**即時失効**し、端末からも消える。
以後その端末で編集・削除するには再認証が必要。

## 端末を紛失した／その端末を操作できないとき

操作できない端末のトークンだけを個別に消す方法はない（トークンの平文は本人しか持たない）。
**スタッフキーを変更**すれば、**全端末のトークンが一括失効**する。

手順（管理者）:

1. 受発注管理（order-admin）の「スタッフキー変更」から、**管理者用の回復コード**で新キーに変更する。
   - 変更RPC `admin_rotate_staff_key(回復コード, 新キー)` が走り、内部で
     `staff_devices_revoke_all()` により**全端末トークンを失効**する。
2. これで紛失端末を含む**すべての端末**が使えなくなる。
3. 現場の各端末で、新しいスタッフキーを一度入力して**再認証**する（各端末で新トークンが発行される）。

> 注意: スタッフキー変更は「起動時の4桁コード」とは別物。長いスタッフキー＋回復コードが必要。
> 回復コード自体の再設定は Supabase の SQL Editor でのみ行う。

## 監査

- 端末登録・失効は `security_events`（`device_registered` / `device_revoked` /
  `staff_key_rotated`）に記録。
- 個体データの作成・更新・論理削除・復元・番号変更は `individual_audit`（追記のみ）に記録。

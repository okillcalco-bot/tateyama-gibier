# スタッフ認証と端末トークン（個体データの編集・削除）

館山ジビエセンターの現場・事務の端末は**共有**が前提。個体データ（市役所提出データ）
の**編集・削除**は、なりすまし・改ざんを防ぐためスタッフ認証を必須にしている。

## しくみ

- **新規の捕獲登録はスタッフ認証不要**（捕獲者が自分で入力できる。列ホワイトリスト方式の
  公開RPC `public_capture_submit` 経由。買取金額・肉ランク・放射能結果などは設定不可）。
- **既存データの編集・削除・個体番号変更**はスタッフ認証が必要。
  - 端末に**生のスタッフキーは保存しない**。
  - 初回だけスタッフキーを入力すると、その端末に**端末トークン**が発行される。
  - DBには**トークンのsha256ハッシュのみ**保存（表 `staff_device_tokens`）。
  - 以後この端末では**再入力不要**。**最終利用から30日**で自動失効（スライド式）。

localStorage に入るのは `tg_device_token`（トークン。生キーではない）。

## 端末の認証を解除したいとき（共有端末・紛失・貸与終了）

各画面（捕獲票入力 / 業務OSの個体一覧 / 搬入一覧）の
**「🔓認証解除」ボタン**を押す。その端末のトークンが**即時失効**し、端末からも消える。
以後その端末で編集・削除するには再認証が必要。

## 端末を紛失した／その端末を操作できないとき

操作できない端末のトークンだけを個別に消す方法はない（トークンの平文は本人しか持たない）。
**スタッフキーを変更**すれば、**全端末のトークンが一括失効**する。

手順（管理者）:

1. 受発注管理（order-admin）の「スタッフキー変更」から、**管理者用の回復コード**で新キーに変更する。
   - 変更RPC `admin_rotate_staff_key(回復コード, 新キー)` が走り、内部で
     `staff_devices_revoke_all()` により**全端末トークンを失効**する。
2. これで紛失端末を含む**すべての端末**が使えなくなる。
3. 現場の各端末で、新しいスタッフキーを一度入力して**再認証**する（各端末で新トークンが発行される）。

> 注意: スタッフキー変更は「起動時の4桁コード」とは別物。長いスタッフキー＋回復コードが必要。
> 回復コード自体の再設定は Supabase の SQL Editor でのみ行う。

## 監査

- 端末登録・失効は `security_events`（`device_registered` / `device_revoked` /
  `staff_key_rotated`）に記録。
- 個体データの作成・更新・論理削除・復元・番号変更は `individual_audit`（追記のみ）に記録。

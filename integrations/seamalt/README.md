# シーモルト連携（館山ジビエ受発注 ⇄ ChatGPT dot「シーモルト」）

**状態: 連携準備中（ローカル実装・試験済み／本番未適用・未接続）。「連携済み」ではありません。**

## 何ができるようになるか（承認・接続後）
シーモルトに「今週届いた注文を確認して、未登録の分を登録して」と頼むと:
1. シーモルトが接続済みのメールで本文と添付PDFを読み、注文を抽出する（メール読取はシーモルト側の機能）
2. `orders_search` で既存の注文・出荷・請求・取消と照合（ページ送りを最後まで）
3. 「登録して」と頼まれたときだけ `order_import_preview` で取込候補を保存し、確認が要る点をまとめて聞く
4. 確認後 `order_import_commit` で既存の受注（orders/order_items）に「受注」として登録
5. `orders_get` で読み直して一致を報告（受注番号・外部注文ID・状態・受発注画面へのリンク）

登録するのは「受注」だけ。在庫の確保・納期や価格の約束・出荷・請求・お客さんへの返信はしません。

## どこで人に聞くか（シーモルトが止まって確認する点）
- 顧客台帳に無い店・同じ名前の店が複数（顧客は作らない。既存画面で登録してもらう）
- 商品名が価格マスタの部位名と違う（例「肩」→カタ？）。確認した対応は次回から使う
- 同じ顧客・近い日付・同じ部位の既存注文（手入力・BASE・直接出荷）がある → 同じ注文か別か
- 同じ注文番号で内容が違う（変更・取消）→ 上書きせず、元注文と出荷・請求の状態を示す
- 注文書の番号が読めない

## 受注に「要確認」として入るもの（受発注画面で確認してから先へ）
- 温度帯の記載がない／「フレッシュ」の意味（冷蔵か）／枝肉の頭数注文
- 要確認のうちは、確認済・出荷・引当・請求書作成が DB 側で止まります（画面にも赤いバッジ）。
  受発注管理の注文詳細「シーモルト取込」欄で温度帯を選び「確認した」→ 通常の受注として進められます。
- 本・頭の注文は重量・金額が未確定のまま（出荷時の実重量で決まる）。画面では「未確定」と表示。
- 注意: ヤマトB2 CSV の荷扱いは今も常に「冷凍」で出ます。冷蔵の取込注文は送り状で直してください。
